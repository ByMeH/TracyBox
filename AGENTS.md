# TraceBox — инструкции для AI-агентов

TraceBox — локальное PyQt6-приложение для организации CTF-заданий и базового анализа файлов. Интерфейс приложения — на русском языке. Приложение не требует сети и не использует внешние AI API.

## Приоритеты проекта

1. Рабочий и понятный функционал важнее количества строк и количества файлов.
2. Реализуем сначала Core из `docs/PROJECT_BRIEF.md`. Дополнительные функции — только после проверки Core.
3. Не расширяй требования самостоятельно. При неоднозначности выбери простое решение и коротко обозначь допущение.
4. Не добавляй зависимости без реальной необходимости. Перед добавлением новой зависимости объясни, зачем она нужна.

## Стиль Python

- Следуй PEP 8 и используй говорящие имена.
- Пиши простые функции и классы с одной ясной ответственностью.
- Добавляй type hints там, где они улучшают понимание публичных интерфейсов; не усложняй ими очевидный локальный код.
- Не создавай абстракции, базовые классы, фабрики, менеджеры и слои «на будущее» без конкретной потребности.
- Не дублируй логику. Но и не объединяй несвязанные операции в универсальные функции.
- Не гонись за количеством строк. Код должен быть содержательным и объяснимым автору проекта.
- Не оставляй заглушки, фиктивные данные, `pass`, `TODO` или функции, которые только имитируют работу, если это не согласовано явно.

## Комментарии и документация к коду

- Не комментируй очевидное: `# создаём кнопку`, `# сохраняем данные`, `# возвращаем результат` запрещены.
- Не добавляй комментарий к каждой функции и строке.
- Не пиши длинные шаблонные docstring с пересказом имени функции.
- Комментарий нужен только для объяснения причины решения, нетривиального алгоритма, ограничения или неожиданного поведения.
- Не добавляй декоративные разделители и комментарии, похожие на автогенерированный шаблон.
- Документацию пиши ясным естественным русским языком, без рекламных формулировок.

## Архитектура

- Сохраняй небольшую модульную структуру: точка входа, главное окно/диалоги, слой БД и репозитории, инструменты анализа, экспорт.
- Не помещай SQL и бизнес-логику непосредственно в обработчики кнопок.
- Не делай отдельный модуль для каждой мелочи.
- GUI отвечает за отображение, ввод и сообщения пользователю; работа с данными находится в соответствующих модулях.
- Используй сигналы и слоты Qt. Не блокируй интерфейс длительными операциями; не добавляй потоки для мгновенных локальных операций.

## SQLite и файлы

- Используй стандартный `sqlite3`, без ORM.
- Включай `PRAGMA foreign_keys = ON` для соединения.
- Все значения в SQL передавай параметрами (`?`), никогда не собирай запрос из пользовательского ввода.
- Изменения нескольких связанных записей выполняй транзакционно.
- Соблюдай внешние ключи и осмысленные `ON DELETE` правила.
- Для чтения файлов используй `pathlib`; большие файлы хешируй блоками, а не целиком в памяти.
- Анализ файлов не должен изменять исходный файл. Не копируй его в хранилище без явной необходимости.
- Ошибки на границе GUI показывай понятным сообщением, технические подробности не скрывай при отладке.

## Тестирование

- Проверяй чистую бизнес-логику и работу репозиториев через `pytest`.
- Для SQLite используй временную БД из `tmp_path`, а не пользовательскую базу проекта.
- Сначала запускай относящийся к изменению тест, затем весь набор тестов перед завершением этапа.
- Не утверждай, что тесты прошли, если команда не запускалась.
- Исправляй первопричину ошибки, не маскируй её широкими `except Exception`.

## Экономия времени и токенов

- Перед изменением изучи только нужные файлы и связанные вызовы. Не перечитывай весь проект без причины.
- Не выводи и не пересказывай целиком файлы, которые не менялись.
- Не делай массовый рефакторинг ради локальной задачи.
- За один проход решай одну законченную задачу. После изменения покажи краткий итог: файлы, поведение, проверки и оставшиеся ограничения.
- Не запускай длинные цепочки команд и повторные проверки без причины.
- Не используй платные API и не добавляй AI-функции в само приложение.

## Работа с Git

- Не выполняй `git commit`, `git push`, `git reset`, `git clean` и другие изменяющие историю/рабочее дерево команды без явной просьбы пользователя.
- Не перезаписывай пользовательские изменения. Перед крупными изменениями проверяй `git status` и `git diff`.
- Не добавляй `.venv`, базы с пользовательскими данными, кэш, сборки и секреты в Git.
