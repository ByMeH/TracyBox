# TraceBox — техническое задание

**Версия:** 1.0  
**Тип приложения:** локальное настольное приложение  
**Стек:** Python 3.14, PyQt6, SQLite (`sqlite3`)

## 1. Назначение

TraceBox — рабочее пространство для учащихся и начинающих участников CTF. Приложение помогает вести соревнования и задания, сохранять заметки и сведения об исследуемых файлах, выполнять несколько базовых операций с текстом и файлами.

Приложение работает локально. Для обычной работы не нужны регистрация, сервер, интернет или внешний AI API.

## 2. Цели первой версии

Пользователь должен иметь возможность:

1. Создавать и редактировать CTF-соревнования.
2. Добавлять задания к соревнованиям и отслеживать их статус.
3. Сохранять заметки по каждому заданию.
4. Добавлять в карточку задания сведения о локальных файлах и вычислять SHA-256.
5. Вычислять MD5, SHA-1 и SHA-256 для выбранного файла.
6. Кодировать и декодировать текст в Base64, Hex и URL-кодировке.
7. Просматривать сводную статистику и экспортировать данные выбранного соревнования в CSV или TXT.

## 3. Пользователь и ограничения

- В приложении одна локальная роль пользователя; авторизации нет.
- Одно задание обязательно принадлежит одному соревнованию.
- Заметка и запись об артефакте обязательно принадлежат одному заданию.
- Приложение не исполняет, не распаковывает и не модифицирует исследуемые файлы.
- Артефакт — это запись о файле, а не копия файла. На диске сохраняется только путь и вычисленные метаданные.
- Удаление записи об артефакте не удаляет исходный файл.
- Удаление соревнования удаляет его задания, заметки и записи об артефактах из БД. Файлы на диске остаются нетронутыми.
- Категория задания — обычный текст, а не отдельный справочник.
- Интерфейс первой версии — на русском языке.

## 4. Функциональные требования

### FR-01. Обзор

Главная вкладка показывает:

- общее количество соревнований;
- общее количество заданий;
- количество решённых заданий;
- процент решённых заданий;
- количество заданий по статусам;
- несколько последних добавленных или изменённых заданий.

При пустой базе показывается понятное сообщение и предложение создать первое соревнование.

**Приёмка:** показатели пересчитываются после добавления, изменения и удаления данных; приложение корректно показывает нулевые значения.

### FR-02. Соревнования

Пользователь может создать, просмотреть, изменить и удалить соревнование.

Поля:

- название — обязательно;
- организатор или платформа — необязательно;
- ссылка — необязательно;
- дата начала — необязательно;
- описание — необязательно.

Название после удаления пробелов по краям не может быть пустым. Ссылка не должна быть обязательной для локального использования.

**Приёмка:** все четыре операции работают; пустое название не сохраняется; удаление соревнования требует подтверждения и явно предупреждает об удалении связанных записей TraceBox.

### FR-03. Задания

Пользователь может создать, просмотреть, изменить и удалить задание.

Поля:

- соревнование — обязательно;
- название — обязательно;
- категория — необязательно, свободный текст;
- сложность — «Лёгкая», «Средняя» или «Сложная»;
- статус — «Новое», «В работе», «Решено» или «Пропущено»;
- стоимость в баллах — необязательно, целое число от 0 и выше;
- описание — необязательно.

По умолчанию сложность — «Средняя», статус — «Новое». Задание нельзя сохранить без соревнования и названия.

**Приёмка:** CRUD работает; фильтр по соревнованию и статусу позволяет быстро найти записи; после изменения статуса обзор показывает новые значения.

### FR-04. Заметки

В окне подробностей задания пользователь может добавлять, просматривать, изменять и удалять заметки.

Поля заметки: заголовок и текст. Заголовок и текст обязательны. Для заметки автоматически сохраняются дата создания и дата последнего изменения.

**Приёмка:** заметка связана с выбранным заданием; изменение обновляет дату изменения; удаление затрагивает только выбранную заметку.

### FR-05. Артефакты

В окне подробностей задания пользователь может выбрать существующий файл и добавить запись о нём.

Для файла сохраняются:

- абсолютный путь;
- имя файла;
- размер в байтах;
- SHA-256;
- дата добавления записи.

SHA-256 вычисляется при добавлении файла потоковым чтением блоками. Файл не копируется в каталог приложения. При просмотре записи приложение может проверить, существует ли путь. Отсутствующий файл показывается как недоступный; запись остаётся в БД.

**Приёмка:** можно добавить файл, увидеть его метаданные и удалить запись; удаление записи не удаляет файл; ошибка чтения файла не приводит к созданию неполной записи.

### FR-06. Хеширование

Пользователь выбирает файл через стандартный диалог открытия файла. Приложение вычисляет MD5, SHA-1 и SHA-256 за один проход, обновляя три объекта `hashlib` блоками не более 1 МиБ.

MD5 и SHA-1 показываются как контрольные суммы для совместимости и идентификации, а не как современные криптографически стойкие средства защиты.

**Приёмка:** результаты совпадают с известными значениями для тестовых файлов; пустой файл обрабатывается; ошибки доступа показываются понятным сообщением; содержимое файла не меняется.

### FR-07. Кодировщики

Вкладка инструментов поддерживает:

- Base64: кодирование и декодирование UTF-8 текста;
- Hex: преобразование UTF-8 текста в шестнадцатеричную строку и обратно;
- URL: кодирование и декодирование строки.

Для каждой операции есть поле ввода, поле результата и кнопка копирования результата. Ошибочный Base64, некорректный Hex или результат, который нельзя декодировать как UTF-8, должен приводить к понятному сообщению, а не к аварийному завершению.

**Приёмка:** для каждой пары операций выполняются тесты round-trip; некорректный ввод обрабатывается контролируемо.

### FR-08. Экспорт

Пользователь выбирает соревнование и экспортирует его данные:

- CSV — таблица заданий, UTF-8 with BOM (`utf-8-sig`), разделитель `;`;
- TXT — читаемый текстовый отчёт с названием соревнования и списком заданий.

В отчёт включаются основные поля задания: название, категория, сложность, статус, баллы и описание. В TXT дополнительно можно включить заметки и сведения об артефактах. Экспорт не изменяет данные БД.

**Приёмка:** файлы открываются после экспорта; кириллица не повреждается; отмена диалога сохранения ничего не экспортирует и не показывает ошибку.

## 5. Интерфейс

Главное окно содержит вкладки:

1. **Обзор** — статистика и последние задания.
2. **Соревнования** — таблица соревнований и действия CRUD.
3. **Задания** — таблица заданий, фильтры и открытие подробностей.
4. **Инструменты** — вкладки «Хеширование» и «Кодировщики».

Подробности задания открываются в отдельном диалоге с вкладками «Описание», «Заметки» и «Файлы».

Формы создания и редактирования должны проверять ввод до сохранения. Для выбора файлов и путей используются `QFileDialog`; для подтверждений и ошибок — `QMessageBox`.

Используемые виджеты должны иметь практический смысл. Базовый набор: `QMainWindow`, `QTabWidget`, `QTableWidget`, `QLabel`, `QPushButton`, `QLineEdit`, `QTextEdit` или `QPlainTextEdit`, `QComboBox`, `QSpinBox`, `QDateEdit`, `QCheckBox`, `QListWidget`, `QProgressBar`, `QGroupBox`, `QStatusBar`. Если конкретный виджет не нужен для реального сценария, его не следует добавлять только ради формального списка.

В интерфейсе используется локальная SVG-иконка приложения. Не загружать изображения из интернета во время работы программы.

## 6. Нефункциональные требования

- Python 3.14 и PyQt6.
- Хранение данных — SQLite из стандартной библиотеки.
- Внешние API и сетевые запросы отсутствуют.
- SQL-запросы используют параметры `?` для значений.
- Внешние ключи включены через `PRAGMA foreign_keys = ON` на каждом соединении.
- Файлы хешируются потоково.
- Длительные операции не должны выполняться без необходимости; для файлов обычного размера в MVP допустимо синхронное хеширование с индикацией. Если тесты покажут заметную блокировку интерфейса на больших файлах, фоновое выполнение можно вынести за пределы обязательного объёма.
- Пути к данным пользователя не зависят от текущей рабочей директории проекта.
- Ошибки ввода-вывода и БД обрабатываются на границе, где можно показать пользователю осмысленное сообщение.

## 7. Хранение данных

Файл БД по умолчанию: `~/.tracebox/tracebox.db`. Каталог создаётся автоматически. Путь к БД должен передаваться функции подключения параметром, чтобы тесты могли использовать временную БД.

Структура состоит из четырёх таблиц: `competitions`, `challenges`, `notes`, `artifacts`. Поля и ограничения описаны в `ARCHITECTURE.md`.

## 8. Проверки и критерии готовности

Обязательные автоматические тесты:

- хеширование пустого и обычного файла;
- потоковое хеширование файла, размер которого больше одного блока;
- Base64/Hex/URL round-trip;
- обработка некорректного входа декодеров;
- создание, чтение, изменение и удаление соревнования и задания;
- каскадное удаление связанных записей;
- добавление и удаление заметки и артефакта;
- экспорт с кириллицей.

Релиз-кандидат готов, если:

1. Все обязательные сценарии из FR-01—FR-08 работают.
2. Тесты проходят командой `pytest`.
3. БД создаётся автоматически при первом запуске.
4. Приложение запускается из чистого виртуального окружения по README.
5. Сборка Windows EXE выполняется на Windows runner через GitHub Actions или на Windows-машине. PyInstaller не следует запускать на Arch в надежде получить Windows EXE: сборку выполняют на целевой ОС.
6. В репозиторий не попадают `.venv`, пользовательская БД, секреты и сборочные каталоги.

## 9. Вне первой версии

Не входят в MVP: пользовательские аккаунты, облачная синхронизация, сетевые функции, интеграция AI API, выполнение или автоматический анализ подозрительных файлов, полноценная цифровая криминалистика, анализ строк, Hex Viewer, сравнение файлов, плагины, теги, миграции БД, сложная система настроек и кастомизации.
