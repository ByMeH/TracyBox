# TraceBox — краткое описание проекта

## Назначение

TraceBox — настольное офлайн-приложение на PyQt6 для ведения CTF-соревнований и заданий, хранения заметок и учёта исследуемых файлов. Встроенные утилиты помогают выполнять несколько базовых операций при решении задач.

## Целевая аудитория

Учащиеся и начинающие участники CTF, которым нужно держать соревнования, задания, артефакты и результаты анализа в одном месте.

## Основной сценарий

Пользователь создаёт соревнование, добавляет в него задание, записывает категорию/сложность/статус, прикрепляет сведения об исследуемом файле, вычисляет его хеш, сохраняет заметки и при необходимости экспортирует отчёт.

## Функции первой версии (Core)

1. Dashboard: число соревнований и заданий, распределение заданий по статусам, последние записи.
2. Competitions: создание, просмотр, редактирование и удаление соревнований.
3. Challenges: CRUD заданий, связь с соревнованием, категория, сложность, статус и описание.
4. Notes: заметки, связанные с заданием.
5. Artifacts: учёт выбранных пользователем файлов, путь, имя, размер и SHA-256; исходники не изменяются.
6. Hashing: MD5, SHA-1 и SHA-256 с потоковым чтением файла.
7. Encoders: Base64, Hex и URL-кодирование/декодирование.
8. Reports: экспорт выбранных данных в CSV и TXT.

## После Core, если останется время

Анализ печатных строк, просмотр Hex, дополнительные метаданные и сравнение файлов. Эти функции не должны задерживать завершение Core.

## Ограничения

- Приложение работает локально и не требует интернета.
- Внешние AI API не входят в приложение.
- Для хранения данных используется SQLite.
- Не заявлять полноценную цифровую криминалистику: это учебный CTF-workspace с базовыми утилитами.
- Не исполнять исследуемые файлы и не менять их содержимое.

## Предварительная структура модулей

- `main.py` — запуск приложения.
- `database.py` — соединение, схема и инициализация SQLite.
- `repositories.py` — запросы и CRUD для сущностей.
- `tools.py` — хеширование и преобразование данных.
- `reports.py` — экспорт CSV/TXT.
- `dialogs.py` — диалоги добавления и редактирования.
- `main_window.py` — главное окно и связывание интерфейса с логикой.

Структура предварительная: менять её можно, если есть конкретная причина и это упрощает проект.

## Предварительная модель данных

- `competitions`: соревнования.
- `challenges`: задания, принадлежащие соревнованию.
- `notes`: заметки, связанные с заданием.
- `artifacts`: сведения о файлах, связанные с заданием.

Точные поля, ограничения и правила удаления определить в техническом задании до реализации БД.
